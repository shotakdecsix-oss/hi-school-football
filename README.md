# hi-school-football

高校サッカー監督シミュレーション。サーバーなしの静的PWA、素のJavaScript（ESモジュール、ビルドなし）。
設計書は claude.ai の Project「高校サッカー監督」（`claude/設計書.md` ほか）。

## 現在地: 段階2（試合エンジン v1）の途中
段階1（土台）: メートル基準・20Hz固定刻み、ボール物理、保存と復元、端末間で同じ結果になる乱数・数学、一括実行、2D表示、自動テスト。

段階2で入れたもの（`ENGINE_VERSION` 12）:
- 能力32個（`engine/abil.js`）を使った実行（パス・シュートのばらつき、ファーストタッチ、タックル、GKの反応）
- ボール保持者の判断（`engine/decide.js`）: パス・スペースへのパス・シュート・ドリブル・クリアを点数で比べて選ぶ
- 保持者以外の動き（`engine/brain.js`）: ボールに合わせて動く陣形、サポート、裏への抜け出し、プレス・カバー・マーク。
  持ち場にいる選手は「陣形上の隣」の動きに合わせて連鎖して動く（ボールに近い側から遠い側へ伝わる。攻撃中は横の広がりを保つ）
- ボールを運ぶ動き（`engine/decide.js` の `carryOptions`）: 前・斜め・横・斜め後ろの7方向 × 近く/遠くを、運んだ先の価値・相手の圧力が減る分・
  今の勢い・途中で奪われる危険で採点。ボールを受けた直後も止まらず運び出し（相手から離れる・空いた方・今の勢いの向き）、持ち続けるほど味方を探してパスする。
  走りながら運ぶと、速いほど・強く寄せられるほどタッチミスでボールが離れる（`brain.js` の `carryBall`）
- 見る目（`tools/viewer.html` の「役割の色」）: 保持者と、各選手の今の役割を色で表示
- 大会ごとの試合規定（`data/rules.js`、入力の `rules`）: 選手権系80分・インターハイ系70分・リーグ戦90分など。ノックアウト戦で同点なら延長（前後半を入れ替えて続ける）。
  根拠は Project の「試合エンジンの合格ライン」。神奈川の要項は未確認で、選手権系は埼玉の要項に合わせている
- 再開（スローイン・ゴールキック・コーナー）: ボールが出ると、蹴る選手（GK／一番近い選手／クロスの上手い選手）がボールの脇へ歩いていき、着いてから蹴る。
  相手はスロー2m・コーナー9.15m離れ、ゴールキックはペナルティエリアの外へ出る。コーナーはヘディングの強い4人がゴール前に入る。
  ボールを持ったときの最初のプレーは蹴るだけ（運ぶ・撃つ・クリアはしない）。待ち時間は `engine/consts.js` の `SP_WAIT`、ゴール後は `GOAL_WAIT`
- PK戦（`engine/pk.js`）: ノックアウト戦で延長でも同点のとき。全員が同じゴールへ、先攻はコイントス、5本ずつ→サドンデス（残りを全部決めても追いつけなければ途中で決着）。
  キッカーはシュートと落ち着きが強い順（GKは最後）。蹴る瞬間にGKが跳ぶ向きを決める。1本ごとの結果は ゴール約75%・セーブ約17%・外れ約8%（実際の水準に合わせた）。
  蹴らない選手はセンターサークルで待つ。ログは `EV.PK`（開始）・`EV.PKK`（1本ごと [t, 9, チーム, キッカー, 結果]）
- 選手交代（入力の `teams[k].bench` と `changes: [{ t, k, type: 'sub', slot, bench }]`）: t のあとの最初の中断（ボールが出た・ゴールのあと）かハーフタイムに、
  そのスロットの選手を控えに替える（役割・持ち場はスロットのまま、能力が控えのものになる）。人数は規定の `subs`（5）まで、機会は `subTimes`（3）回まで
  （中断ごとに1回。ハーフタイム・延長前は数えない。延長はそれぞれ+1）。出場済みの控え・存在しない指定は実行されず、記録 `[t, EV.SUB, チーム, スロット, 控え, 1=実行/0=実行されず]` が残る。
  保存・復元のあとは `N[I.OCC+選手]`（出場者）から能力を作り直す
- ボールを外へ出す頻度の調整: ライン際では、パスの着く速さを「止まるまでにラインを割らない強さ」に抑え（`geom.js` の `groundPass`/`rollRoom`）、
  タッチミスも8割は外へ出さずに収める。逆に、自陣で強く寄せられた選手はタッチラインへ蹴り出すことがある（スローインが実際の頻度に近づく）
- シュート意識とDFの攻撃参加（v9）: ボールを持っている価値 `xt` のゴール前を「ゴールが見える角度」に比例させ、シュートの価値は見込み(xG)が高いほど強気に。パスの成功見積もりは実際のファーストタッチの式（`geom.js` の `touchMean`。圧力で悪化）と同じ。SBはボール側で高く上がり（最大+15m）、逆サイドは絞る。保持者の外を回るオーバーラップ。CBもボールに合わせて高く上がる。守備のラインはゴールライン際に張り付かない（最低13m）
- ゴール前の判断（v11）: ゴール近くで撃てるのに遠い味方へ出す問題の修正。撃つ価値は「相手（シュートコース上は1人ごと×0.75）と圧力で割り引いた見込み」`shotQ` で、同じ式の値を「ゴール前に出た先で持つ価値（xt）」の上限にする `zoneCap`（ゴールラインまで15m以内のみ。9m以内は全面、15mに向けて徐々にゆるめる）。ゴール前の混戦でも、撃てる場面は約8割撃つ。幅を26mまで広げると25〜32mで足踏みして遠目からも撃ちすぎたので狭い。リアルな得点・シュート数から多少ずれても、撃ち合いの面白さを優先する（1試合 得点3.2・シュート33ほど）。テストの「shoot:」が、ゴール前の場面を作って撃つ割合を確かめる
- チーム指示（入力の `teams[k].tactics`、`data/tactics.js` の13項目、各 -1〜+1・省略=0=標準）: 指示から `engine/tactic.js` が数値を作り、`brain.js`・`decide.js` が読む。
  どの指示も 0 のときは「指示なし」と完全に同じ動きになるように作る（足しても 0 なら試合の結果が変わらない。その場合 `ENGINE_VERSION` は上げない）。いま効くのは11項目:
  - 守備の5項目: ライン高さ（ブロック全体の前後。最終ラインは低〜高で約15m動く）、コンパクトさ（縦・横の詰め、ボール側へ寄る、ボールから遠い相手は追わない）、
    プレス開始位置（引いて待つ＝ボールが自陣側に来るまで寄せない／敵陣から＝前線を押し上げる）、プレス強度（寄せる範囲・間合い・近づく速さ・コース切り・タックルの出しやすさ）、
    守り方（ゾーン〜マンツーマン＝マークの探す範囲・付いていける距離・持ち場へ戻る力）
  - 切り替え（失った直後 `onLose`・奪った直後 `onWin`）: ボールを持つチームが入れ替わった tick を `N[I.CHGT]` に持ち、そこから最大6秒の「窓」の間だけ動きが変わる（中断・キックオフで窓は消える）。
    すぐ奪い返す(+) = 窓の間、寄せの強さ・開始位置・ラインを上げ、近い2〜3人が別々の角度から保持者を囲む（ゲーゲンプレス。5秒以内に奪い返す割合が約+12pt）。
    すぐ戻る(-) = 最大4秒、最初の1人は間合いを取り、ほかは全力で戻ってラインを下げる（敵陣で失って3秒後のチームの重心が約4m自陣寄りに）。
    縦に速く(+) = 保持者の判断が速く・前へ進める価値を高く見てリスクを取り、前線が自陣深くからでも走り出す（4秒後のボールの前進 +3m前後）。キープ(-) = 落ち着いて安全に（同 -2m前後）
  - リスク（`risk`）: 後ろの残し方（レストディフェンス）と、パス・運ぶときの失う重み、撃つ意識。安全に(-) は CB 以外の深い選手（SB・守備的な中盤の順）を 1〜3 人ハーフウェー付近に残し、逆サイドの SB も絞る・最終ラインから前線まで少し下がる・失う重み ×1.3・撃つ意識 ×0.9・裏へ走る人 -1。
    冒険する(+) は逆サイドの SB も絞らず、最終ラインから前線までが前へ出て（最大 +10〜14m。全員で攻める）・失う重み ×0.7・撃つ意識 ×1.15・裏へ走る人 +1。実測（標準相手）: 安全 = 失点シュート約-16%・体力が試合終わりで約+0.13・保持率+2、冒険 = ボールより5m以上後ろの人数 5.3→4.3・失点シュート約+15%
  - 幅（`width`）: 広い(+) は攻撃の持ち場の横の広がり ×1.12、逆サイドの選手がボール側へ寄らず持ち場を保つ（寄る割合 0.12→0）、サポートに入る距離を遠く（11→14m）、ハーフスペースとライン間（相手の中盤の線と最終ラインのあいだ）で受ける加点（ポジショナルプレー）。狭い(-) は ×0.8・寄る割合 0.3・近いサポート（8m）。攻撃中のチームの横幅 33 / 41 / 46m（狭 / 標準 / 広）
  - テンポ（`tempo`）: 判断までの時間 ×1.3〜×0.7、パスを出す手間 0.0115〜0.0065（標準 0.010）、持ち続けてよい時間 2.0〜0.9 秒（標準 1.5）、サポートに入る選手の走る強さ。速い(+) は持ち時間 1.4→1.0 秒・前向きのパスの割合が増え（35%→43%）、体力の減りが大きい。ゆっくり(-) はパス本数 -12%（認知あり。標準が認知で少し遅くなったので、判断の遅れを 1.2→1.3 に強めて、従来と同じ効きにした）
  - 攻め方（`attack`）: 行き先の価値を横位置で増減（敵陣のほうが強く効く。±35%）、ウイングの持ち場（内へ絞る ×0.75〜大外 ×1.1）、SB の上がり ×0.6〜×1.3。敵陣の最終盤でボールが通る場所（大外 / ハーフスペース / 中央）: サイド 31/46/23%、標準 14/44/42%、中央 8/38/54%。クロスが無いので、サイドからはシュートが減る（クロスとヘディングを入れたあとに再調整）
  - 5レーンの「同じレーンの前後に重ならない」規則は、陣形が崩れた動きが支配的で測っても効かなかったため入れていない。ハーフスペース・ライン間の加点と、逆サイド保持・サポート距離で表した
  オフサイドトラップは項目だけ用意済みで未接続、組み立ては ④ で接続（`TACTICS` の `on: false`）（`TACTICS` の `on: false`）。試合中の変更は `setTactics(m, k, tactics)`（ビューアのスライダーが使う。入力の記録には残らない）。
- スタミナ（v10。`engine/stamina.js`、状態は `F[F_STA+選手]`。1=万全〜0）: 走ると減り（高速で走るほど急に減る）、遅く動いているあいだは少し回復する。減るほど最高速度・加速度が落ちる
  （標準の試合で外野手の平均は、前半の終わりに0.66・試合の終わりに0.56。最も疲れた選手は0.27前後）。STM（能力）が高いほど減りにくく回復も速い。ハーフタイム・延長前の休憩で +0.15、交代で入る控えは万全。
  強い寄せ・ゲーゲンプレスを続けるチームは、前半に優勢でも後半に息切れする（実測で前半+1.7本→後半-1.5本のシュート差）。最高速度・加速度は `m.vmax0/acc0`（能力から決まる本来の値）から疲れ分を引いて `m.vmax/acc` に作り直す
  強弱の釣り合い（ファウル・オフサイドが無いので、強いプレス・高いラインはスタミナ以外に代償がない）は、それらが入ってから調整する

- 認知（v13。`engine/percept.js`。状態は `F[F_FACE+選手]`＝体の向き・`F[F_SCN+選手]`＝気づき（0〜1）・`N[N_LS+見る選手×22+味方]`＝味方を最後に見た tick）: 「全員がピッチの全部を見えている」をやめ、選手ごとに見えている範囲を持つ。プレー選択の土台。
  - 体の向き: 走っているときは進む向き、止まっているときはボールのほう、ボールを持つ選手は運ぶ先、マークの選手はボールと相手の間。向きを変える速さは敏捷性で決まる（背を向けて受けると前を向くのに時間がかかる）
  - 視野（扇）: 正面は確実に見え、端へ向かって弱まり、背後は見えない。広さは能力「視野」で半角 73〜140°。**ボールを持っている選手は扇が 0.8 倍**（ボールを扱いながらなので）。すぐそばは気配で分かる（相手 6m・味方 10m）。ボールの位置は全員が常に分かる
  - 味方の記憶: 扇の中ではっきり見た味方の位置は、しばらく覚えている（3秒×(0.3+0.7×気づき)）。パスの候補になれるのは「いま見えている（近くを含む）味方」と「少し前に見た味方」だけ。見ていない味方には出さない。再開（キックオフ・セットプレー）の最初のプレーは見渡せるので味方の全員が分かる
  - 気づき（首振り）: 見えていない範囲をどれだけ把握しているか。自由な選手は上がり、ボールを持っている・ボールの近くで守っている・寄せられていると下がる（寄せられた保持者 0.4 前後、自由な保持者 0.8、ボールから遠い味方 1.0）。相手の位置の把握と、味方を覚えていられる長さに効く
  - 能力「視野」の効き方: 扇の広さ（半角 70+3.5×視野 度）、首を振る速さ（毎秒 0.35+0.05×(視野+判断力)/2。気づき・記憶の長さに効く）、判断のばらつき（視野と判断力の平均）、パス候補の距離（10+2.5×視野 m）。視野 18 と 4 の対戦（48試合）は 32勝6分10敗、得点 2.94 対 1.44
  - 判断への効き: 保持者は見えていない味方にはパスを出さない。見えていない相手は、パスコースの危険・圧力・運ぶ先の選択・シュートの見積もり（ブロック・圧力）に 4 割だけ数える（気配）。運ぶときの「今の勢い」は体の向きで決まる。ボールを持っていて、扇の外（首も振っていない）から相手に寄せられると、ボールを守れない（`blindOf`）
  - 守備への効き: マークの選手は、見えていない相手を少し前（最大0.5秒。予測が高いほど短い）の位置にいると思って守る（背後の走り込みに遅れる）。体の向きと逆へ動き出すと加速が落ちる（最大 ×0.75）
  - 実測（標準どうし48試合×80分。認知なし → あり）: パス（1チーム1試合）673 → 543（-19%）、シュート（両チーム計）33.7 → 48.9、得点 3.3 → 3.9、ドリブル（1チーム）676 → 938、パス成功率 80% のまま。パスの受け手（非再開・8試合×20分）: 扇の中 64%・近く 7%・扇の端 17%・覚えていただけ 12%・全く知らない 0%。保持者から見て味方（4〜35m）のうち見えていない割合 35%
  - 気をつけること: 認知を入れる・保持者の扇を狭めると、リーグ全体ではシュート・得点が増える（同じ強さの2チームの平均）。これは認知そのものの効果ではなく、判断の価値の見積もり（パス・運ぶ）が実際より高めで、パスの選択肢が減ると前へ運ぶ・撃つほうへ寄るため（比べた記録は Project の「認知層の記録」）。1対1の対戦では、視野が広い・扇が広いほうが勝つ
  - 外す・比べる: 入力 `percept: 0`（`sampleInput(seed, { percept: 0 })`）、`node tools/batch.js --noPercept`、ビューアの「認知」チェック。外すと従来の動き（基準値にも残してある）
  - 今は無いもの: GK の視野、声かけ（見えていなくても聞こえる）、首を振る動きの表示、見えていない味方を探すために体の向きを変える動き（向きはボールか進む向きだけで決まる）

まだ無いもの: オフサイド、ファウル・警告、FK、クロスとヘディングの競り合い（コーナーが実際より少ない）、攻撃の指示のうち組み立て、特性。
数値の目標（1試合の得点・シュートは選手権の実データ、パスなどは仮。実データから多少ずれてもエンタメ性を優先してよい）は Project の「試合エンジンの合格ライン」にある。

## コマンド
PowerShell 5.x は `&&` が使えないので `;` で区切る。

```
node tools/test.js                       # 自動テスト（npm test でも可）
node tools/batch.js --n 50 --check       # 同じ設定で50試合（既定は選手権系の80分）。--check は再現性も確認。--rules / --ko で規定を変える
node tools/batch.js --n 16 --noPercept  # 認知（向き・視野）なしで走らせる（比べる用）。認知ありのときは「認知」の表も出る
node tools/batch.js --n 16 --tacH line=1,compact=1   # チーム0に指示（--tacA でチーム1）。守備のブロックの表（最終ライン・縦横幅・寄せ人数）も出る（--def で指示なしでも出す）
#   いつも出る表: 切り替え（失った回数・5秒以内の奪回・8秒以内の被シュート・奪って4秒後の前進・後ろに残る人数）、スタミナ（前半の終わり→試合の終わり）、前半/後半のシュート
node tools/golden.js --write             # 基準値の更新（エンジンを意図して変えたときだけ）
```

## ブラウザで見る
ESモジュールはファイルを直接開いても動かない。デプロイ先（Vercel）のURLで開く。
- `/tools/viewer.html` … 試合を上から見る（速度×1〜×60）。「戦術」を開くと、両チームの指示（攻撃・守備・切り替えの11項目）を5段階のスライダーで変えられる（途中で動かすとその場から効く）。上のバーに両チームのスタミナ（外野手の平均）も出る。「認知」のチェックで認知のあり・なしを切り替えられる（切り替えると最初からやり直す。同じ種で見比べられる）。「視野」は 一人 / 全員 / なし: 白い線が体の向き、扇が視野（濃いほど確実に見える）。「一人」はボールを持っている選手の目線で（保持者の扇は狭い）、見えていない選手は薄くなる。点線の輪は気配で分かる範囲（黄=相手 6m、水色=味方 10m）、黄の点線の小さな輪は「覚えているだけ」の味方。選手をクリックするとその選手の目線になる（もう一度クリックで保持者に戻る）。上のバーに目線の選手の「気づき」も出る
- `/tools/check.html` … この端末で試合が基準値と同じ展開になるか（iPhoneのSafariでも確認できる）


## エンジンの決まり（試合の再現性のため）
- `engine/` の中では Math の sin/cos/atan2/exp/log/pow/hypot/random、`**`、Date、performance を使わない。
  代わりに `engine/core/math.js` の関数を使う（`tools/test.js` が検査する）。
- 乱数は `hash4(試合の種, tick, 選手, 用途)` のように、用途と対象から作る（順番に依存しない）。
- 試合の状態は `F`（Float64Array）・`N`（Int32Array）・`log` だけ。AIの内部状態もここに入れる。
- エンジンの結果が変わる修正をしたら `ENGINE_VERSION` を上げ、`golden.json` を更新する。
