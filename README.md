# hi-school-football

高校サッカー監督シミュレーション。サーバーなしの静的PWA、素のJavaScript（ESモジュール、ビルドなし）。
設計書は claude.ai の Project「高校サッカー監督」（`claude/設計書.md` ほか）。

## 現在地: 段階2（試合エンジン v1）の途中
段階1（土台）: メートル基準・20Hz固定刻み、ボール物理、保存と復元、端末間で同じ結果になる乱数・数学、一括実行、2D表示、自動テスト。

段階2で入れたもの（`ENGINE_VERSION` 9）:
- 能力32個（`engine/abil.js`）を使った実行（パス・シュートのばらつき、ファーストタッチ、タックル、GKの反応）
- ボール保持者の判断（`engine/decide.js`）: パス・スペースへのパス・シュート・ドリブル・クリアを点数で比べて選ぶ
- 保持者以外の動き（`engine/brain.js`）: ボールに合わせて動く陣形、サポート、裏への抜け出し、プレス・カバー・マーク。
  持ち場にいる選手は「陣形上の隣」の動きに合わせて連鎖して動く（ボールに近い側から遠い側へ伝わる。攻撃中は横の広がりを保つ）
- ボールを運ぶ動き（`engine/decide.js` の `carryOptions`）: 前・斜め・横・斜め後ろの7方向 × 近く/遠くを、運んだ先の価値・相手の圧力が減る分・
  今の勢い・途中で奪われる危険で採点。ボールを受けた直後も止まらず運び出し（相手から離れる・空いた方・今の勢いの向き）、持ち続けるほど味方を探してパスする。
  走りながら運ぶと、速いほど・強く寄せられるほどタッチミスでボールが離れる（`brain.js` の `carryBall`）
- 見る目（`tools/viewer.html` の「役割の色」）: 保持者と、各選手の今の役割を色で表示
- 大会ごとの試合規定（`data/rules.js`、入力の `rules`）: 選手権系80分・インターハイ系70分・リーグ戦90分など。ノックアウト戦で同点なら延長（前後半を入れ替えて続ける）。
  根拠は Project の「試合エンジンの合格ライン」。神奈川の要項は未確認で、選手権系は埼玉の要項に合わせている
- 再開（スローイン・ゴールキック・コーナー）: ボールが出ると、蹴る選手（GK／一番近い選手／クロスの上手い選手）がボールの脇へ歩いていき、着いてから蹴る。
  相手はスロー2m・コーナー9.15m離れ、ゴールキックはペナルティエリアの外へ出る。コーナーはヘディングの強い4人がゴール前に入る。
  ボールを持ったときの最初のプレーは蹴るだけ（運ぶ・撃つ・クリアはしない）。待ち時間は `engine/consts.js` の `SP_WAIT`、ゴール後は `GOAL_WAIT`
- PK戦（`engine/pk.js`）: ノックアウト戦で延長でも同点のとき。全員が同じゴールへ、先攻はコイントス、5本ずつ→サドンデス（残りを全部決めても追いつけなければ途中で決着）。
  キッカーはシュートと落ち着きが強い順（GKは最後）。蹴る瞬間にGKが跳ぶ向きを決める。1本ごとの結果は ゴール約75%・セーブ約17%・外れ約8%（実際の水準に合わせた）。
  蹴らない選手はセンターサークルで待つ。ログは `EV.PK`（開始）・`EV.PKK`（1本ごと [t, 9, チーム, キッカー, 結果]）
- 選手交代（入力の `teams[k].bench` と `changes: [{ t, k, type: 'sub', slot, bench }]`）: t のあとの最初の中断（ボールが出た・ゴールのあと）かハーフタイムに、
  そのスロットの選手を控えに替える（役割・持ち場はスロットのまま、能力が控えのものになる）。人数は規定の `subs`（5）まで、機会は `subTimes`（3）回まで
  （中断ごとに1回。ハーフタイム・延長前は数えない。延長はそれぞれ+1）。出場済みの控え・存在しない指定は実行されず、記録 `[t, EV.SUB, チーム, スロット, 控え, 1=実行/0=実行されず]` が残る。
  保存・復元のあとは `N[I.OCC+選手]`（出場者）から能力を作り直す
- ボールを外へ出す頻度の調整: ライン際では、パスの着く速さを「止まるまでにラインを割らない強さ」に抑え（`geom.js` の `groundPass`/`rollRoom`）、
  タッチミスも8割は外へ出さずに収める。逆に、自陣で強く寄せられた選手はタッチラインへ蹴り出すことがある（スローインが実際の頻度に近づく）
- シュート意識とDFの攻撃参加（v9）: ボールを持っている価値 `xt` のゴール前を「ゴールが見える角度」に比例させ、シュートの価値は見込み(xG)が高いほど強気に。パスの成功見積もりは実際のファーストタッチの式（`geom.js` の `touchMean`。圧力で悪化）と同じ。SBはボール側で高く上がり（最大+15m）、逆サイドは絞る。保持者の外を回るオーバーラップ。CBもボールに合わせて高く上がる。守備のラインはゴールライン際に張り付かない（最低13m）
- チーム指示（入力の `teams[k].tactics`、`data/tactics.js` の13項目、各 -1〜+1・省略=0=標準）: 指示を省略した試合は v9 と完全に同じ結果（`ENGINE_VERSION` は 9 のまま）。
  指示から `engine/tactic.js` が数値を作り、`brain.js` が読む。いま効くのは守備の5項目: ライン高さ（ブロック全体の前後。最終ラインは低〜高で約15m動く）、
  コンパクトさ（縦・横の詰め、ボール側へ寄る、ボールから遠い相手は追わない）、プレス開始位置（引いて待つ＝ボールが自陣側に来るまで寄せない／敵陣から＝前線を押し上げる）、
  プレス強度（寄せる範囲・間合い・近づく速さ・コース切り・タックルの出しやすさ）、守り方（ゾーン〜マンツーマン＝マークの探す範囲・付いていける距離・持ち場へ戻る力）。
  攻撃・切り替え・オフサイドトラップの指示は項目だけ用意済みで未接続（`TACTICS` の `on: false`）。試合中の変更は `setTactics(m, k, tactics)`（ビューアのスライダーが使う。入力の記録には残らない）。
  強弱の釣り合い（スタミナ・ファウル・オフサイドが無いので、プレス強度・高いラインは代償なしで有利）は、それらが入ってから調整する

まだ無いもの: オフサイド、ファウル・警告、FK、クロスとヘディングの競り合い（コーナーが実際より少ない）、スタミナ、攻撃・切り替えの指示、特性。
数値の目標（1試合の得点・シュートは選手権の実データ、パスなどは仮）は Project の「試合エンジンの合格ライン」にある。

## コマンド
PowerShell 5.x は `&&` が使えないので `;` で区切る。

```
node tools/test.js                       # 自動テスト（npm test でも可）
node tools/batch.js --n 50 --check       # 同じ設定で50試合（既定は選手権系の80分）。--check は再現性も確認。--rules / --ko で規定を変える
node tools/batch.js --n 16 --tacH line=1,compact=1   # チーム0に指示（--tacA でチーム1）。守備のブロックの表（最終ライン・縦横幅・寄せ人数）も出る（--def で指示なしでも出す）
node tools/golden.js --write             # 基準値の更新（エンジンを意図して変えたときだけ）
```

## ブラウザで見る
ESモジュールはファイルを直接開いても動かない。デプロイ先（Vercel）のURLで開く。
- `/tools/viewer.html` … 試合を上から見る（速度×1〜×60）。「戦術」を開くと、両チームの守備の指示を5段階のスライダーで変えられる（途中で動かすとその場から効く）
- `/tools/check.html` … この端末で試合が基準値と同じ展開になるか（iPhoneのSafariでも確認できる）

## フォルダ
```
engine/   試合エンジン（画面に依存しない純粋なJS。Worker と Node の両方で動く）
  core/   決定的な数学・乱数・チェック値
sim/      週進行・成長・勧誘・他校・卒業生の人生・セーブ移行（未着手）
data/     県ごとのデータ、フォーメーションなど
ui/       各画面（未着手）
render/   試合の2D/3D描画、顔の生成
tools/    テスト、一括実行、確認ページ
```

## エンジンの決まり（試合の再現性のため）
- `engine/` の中では Math の sin/cos/atan2/exp/log/pow/hypot/random、`**`、Date、performance を使わない。
  代わりに `engine/core/math.js` の関数を使う（`tools/test.js` が検査する）。
- 乱数は `hash4(試合の種, tick, 選手, 用途)` のように、用途と対象から作る（順番に依存しない）。
- 試合の状態は `F`（Float64Array）・`N`（Int32Array）・`log` だけ。AIの内部状態もここに入れる。
- エンジンの結果が変わる修正をしたら `ENGINE_VERSION` を上げ、`golden.json` を更新する。
